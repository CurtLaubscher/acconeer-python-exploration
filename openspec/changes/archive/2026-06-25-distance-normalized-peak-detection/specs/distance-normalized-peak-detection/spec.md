## ADDED Requirements

### Requirement: Distance-normalized peak extraction algorithm
The system SHALL provide a `distance_normalized` peak extraction algorithm that normalizes the summed-velocity distance profile by a distance-varying threshold curve, so that the detection threshold is always 1.0 (dimensionless ratio).

The threshold curve SHALL be: `threshold_curve(d) = max(threshold_max * (1 - d / reference_distance_m), threshold_min)`

The normalized profile SHALL be: `profile / threshold_curve(distances_m)`

Peak detection SHALL reuse the existing scalar threshold compare with `threshold=1.0`.

#### Scenario: Detection above normalized threshold
- **WHEN** the normalized ratio at the argmax distance bin exceeds 1.0
- **THEN** the frame SHALL have status `detected` and `target_distance_m` set to that bin's distance

#### Scenario: No detection below normalized threshold
- **WHEN** the normalized ratio at the argmax distance bin is 1.0 or below
- **THEN** the frame SHALL have status `no_detection`, `target_distance_m` SHALL be None, and `candidate_distance_m` SHALL be set to the distance bin with the highest normalized ratio

#### Scenario: Threshold curve floor
- **WHEN** a distance bin is at or beyond `reference_distance_m`
- **THEN** its threshold curve value SHALL be `threshold_min` (not zero or negative)

### Requirement: Distance-normalized algorithm parameters
The system SHALL accept three parameters for the `distance_normalized` algorithm: `threshold_max` (float, > 0), `threshold_min` (float, > 0, < threshold_max), and `reference_distance_m` (float, > 0).

Default values SHALL be: `threshold_max=1250.0`, `threshold_min=300.0`, `reference_distance_m=0.700`.

#### Scenario: Parameters stored in series metadata
- **WHEN** a detection series is generated with the `distance_normalized` algorithm
- **THEN** `algorithm_params` SHALL contain `threshold_max`, `threshold_min`, and `reference_distance_m`

### Requirement: Generate Detection Series dialog supports distance-normalized algorithm
The Generate Detection Series dialog SHALL include `distance_normalized` as a third algorithm option labeled `"dist normalized"`. When selected, three additional spinboxes SHALL appear for `threshold_max`, `threshold_min`, and `reference_distance_m`. These spinboxes SHALL be hidden for other algorithms.

#### Scenario: Conditional parameter visibility
- **WHEN** user selects `"dist normalized"` in the algorithm combo
- **THEN** the three parameter spinboxes SHALL become visible

#### Scenario: Parameter spinboxes hidden for other algorithms
- **WHEN** user selects `"sum v"` or `"v0 slice"`
- **THEN** the three parameter spinboxes SHALL be hidden

### Requirement: Auto-generated name for distance-normalized series
The system SHALL auto-generate a display name for `distance_normalized` series that includes the reference distance, e.g. `"dist norm, ref 0.70m"`.

#### Scenario: Default name reflects parameters
- **WHEN** a detection series is generated with `distance_normalized` and `reference_distance_m=0.700`
- **THEN** the auto-generated name SHALL contain `"dist norm"` and the reference distance value

### Requirement: Detection ratio strip in rendered heatmap
The rendered heatmap SHALL display a thin strip above the main heatmap axes showing the per-bin detection ratio for the active detection series at the current frame.

The strip SHALL use a colormap where values below 1.0 appear in a cool color ramp and values above 1.0 appear in a warm color ramp, making the detection threshold visually prominent.

When no detection series is active, the strip SHALL render as a blank/neutral row.

The strip height SHALL be a small proportion of the total rendered height (approximately 8%).

The strip x-axis (distance) SHALL be shared with the heatmap axes.

#### Scenario: Strip shows detection ratio for active series
- **WHEN** a detection series is active and a frame is rendered
- **THEN** the strip SHALL display per-bin detection ratio values for that frame using the threshold-split colormap

#### Scenario: Strip is blank with no active series
- **WHEN** no detection series is selected in the "Detection Algorithm" dropdown
- **THEN** the strip SHALL render as a blank neutral row with no data

#### Scenario: Strip present for all three algorithms
- **WHEN** a detection series generated by `sum_velocity`, `zero_velocity_slice`, or `distance_normalized` is active
- **THEN** the strip SHALL populate with that series' per-bin detection ratio
